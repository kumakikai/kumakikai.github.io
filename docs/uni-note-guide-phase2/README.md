## 画像差し替え時

1. `02-image-map.md`から掲載先・原本・CAPセッション・目的を特定する。
2. Phase 1.5の教材と、Phase 2の公開版再評価を使って実アプリを撮影する。
3. `data/uni_guide_images.json`と`implementation-map.json`の対応をそろえる。
4. 実際の画像に合うalt/caption、版、sha256を記録し、採用を確認した新原本は`approved`にする。今回の`legacy-approved`は旧画像の承認状態、`pending`は未入手の非表示状態。
5. 画像レビューとbuild後の限定レビューを更新し、すべての検証を再実行する。

素材入手前にファイルパスや空枠を表示させない。完成画像と手順画像の意味を取り違えず、同じ原本を前後状態として二重計上しない。
